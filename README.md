# Fluxity Finance Landing Page

Fluxity is a token streaming solution designed to enhance the efficiency of financial transactions within the Stellar blockchain ecosystem. By enabling real-time transfer of cryptographic tokens, Fluxity introduces a new paradigm in financial interactions, fostering dynamic ecosystems.

**Token Streaming as a Solution**

Token streaming provides an innovative solution, offering real-time, continuous transactions that can be adapted to various use cases, ensuring attractiveness, flexibility, and trust in financial engagements. It allows for an ongoing flow of tokens, similar to streaming media content, with predefined start and stop times and transfer rates, providing both parties with predictable, fluid transactions. Token streams can be cancellable and offer maximum flexibility to payment configurations at slashed transaction costs.

**Key Features**

- **Flexible Token Streaming**: Choose between linear or exponential token streaming to suit your needs.
- **Cliff Streams**: Delay token distribution to incentivize commitment and discourage speculative behavior.
- **Vesting Streams**: Create streams where tokens unlock daily, weekly, monthly, or yearly based on preferred rates set during creation.

For more information, visit [https://fluxity.finance](https://fluxity.finance/).

## Getting Started

```bash
# 1. Install dependencies
npm install

# 2. (Optional) configure environment variables
cp .env.example .env.local

# 3. Start the dev server (http://localhost:3000)
npm run dev
```

## NPM Scripts

| Script                 | Description                                             |
| ---------------------- | ------------------------------------------------------- |
| `npm run dev`          | Start the development server (hot reload).              |
| `npm run build`        | Production build (also runs the TypeScript type check). |
| `npm run start`        | Serve the production build on port **3002**.            |
| `npm run lint`         | Run ESLint.                                             |
| `npm run lint:fix`     | Run ESLint and auto-fix.                                |
| `npm run typecheck`    | Run `tsc --noEmit` (run after a build).¹                |
| `npm run format`       | Format the codebase with Prettier.                      |
| `npm run format:check` | Verify formatting without writing.                      |

¹ `tsc` relies on `next-env.d.ts`, which is generated by `next build`/`next dev`. Run a build first (or just rely on `npm run build`, which type-checks).

## Environment Variables

| Variable                      | Required | Default                       | Description                                                                               |
| ----------------------------- | -------- | ----------------------------- | ----------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_FLUXITY_API_URL` | No       | `https://api.fluxity.finance` | Base URL of the Fluxity API used by the waitlist subscription form. Validated at runtime. |

> Because it is a `NEXT_PUBLIC_*` value, it is **inlined at build time**. Changing it requires a rebuild (or a Docker build arg — see below). See [`.env.example`](./.env.example).

## Docker

The image uses a multi-stage build on Node 24 Alpine, runs as a non-root user, leverages Next.js standalone output for a small footprint, and includes a container health check.

```bash
# Build & run with Docker Compose
docker compose up -d --build

# …or with plain Docker
docker build -t fluxity-finance:latest .
docker run -p 3002:3002 fluxity-finance:latest
```

The app is then available at [http://localhost:3002](http://localhost:3002).

To bake a non-default API URL into the client bundle, pass a build arg:

```bash
docker build --build-arg NEXT_PUBLIC_FLUXITY_API_URL=https://api.example.com -t fluxity-finance:latest .
```

## Deployment / CI

- **`.github/workflows/ci.yml`** — runs on every push/PR: formatting, lint, and a production build (which also type-checks).
- **`.github/workflows/main.yml`** — runs on `master` on a self-hosted runner: builds the Docker image and (re)deploys it via Docker Compose.

## Security

Baseline security response headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Strict-Transport-Security`, `Permissions-Policy`, `X-DNS-Prefetch-Control`) are configured in [`next.config.ts`](./next.config.ts), and the `X-Powered-By` header is disabled.

A strict `Content-Security-Policy` is intentionally **not** shipped by default because it needs per-deployment tuning (nonces for Next.js's inline runtime). Adding one is recommended for production — see the [Next.js CSP guide](https://nextjs.org/docs/app/guides/content-security-policy).
